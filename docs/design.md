# 首阶段设计：原厂启动链下的 ARM64 探针

## 目标与选择

目标平台为 HP Chromebook x2 11 / Google Coachz（SC7180）。首阶段的成功标准是经原厂 Depthcharge 进入独立引导代码，在 EL1 执行，并取得内存与设备树交接信息。

比较过的路径：

1. **直接 FIT shim（本阶段选择）**：沿用已有开发者模式内核入口，首阶段不需要修改 SPI。需要自己处理 Image ABI、EL2→EL1、FDT、后续 XNU Mach-O / ADT 接口。
2. **RW_LEGACY → U-Boot → EFI**：有 Coachz 社区代码可参考，更接近 UniXNU 的 EFI 入口；但引入 SPI 更新，且原厂分支在 Legacy 交接时也会关闭显示。还必须确认 EFI 实际运行的 EL，不能假定 DarwinBoot 可直接接受。
3. **替换原厂固件／移植整套 Mu-Silicium**：当前没有必要先承担这一层工作，不作为首阶段。

## 组件

- `entry.S` 仅负责 Image 头、栈与 BSS、入口状态快照、EL2→EL1、异常向量。
- `probe.c` 记录诊断状态；不配置 GIC、不启动副核、不加载系统、不访问存储。
- `fdt.c` 提供有界只读属性查找，不执行设备树提供的指针或地址。
- UART 是单独构建选项：只在协议、时钟和字长与原厂初始化状态相符时尝试发送；每次轮询有上限。
- Python 构建工具输出 ELF、原始 Image、最小 DTB、FIT 和哈希清单。签名是独立的文件操作。

## 入口与数据流

输入遵循 Depthcharge 的 ARM64 Linux ABI：`x0 = FDT PA`，`x1..x3 = 0`，当前为 NS EL2，MMU 已关闭。探针也接受已经位于 EL1 的调用。

EL2 分支将 EL1 设置为 AArch64、关闭 stage-2 translation、允许 EL1 使用计时器、配置无 MMU 的 SCTLR_EL1、设置 SP_EL1，再通过 ERET 进入 EL1h。保留上层 EL3 / BL31。此设置只保证本探针需要的执行环境，不声称已经满足完整 XNU、GIC 或 SMP 的初始化契约。

探针将诊断放到 Image 的 BSS 日志区；UART 输出是日志的附加通道。异常处理只写内存日志并停止，避免 UART MMIO 出错时递归访问外设。

## 限制

- 不包含 Apple 固件、XNU 内核或 iPadOS 用户态。
- 不恢复显示、不提供 eMMC / SD / USB / 触摸 / GPU 驱动。
- UART 的寄存器来自固定上游源码，实际是否处于可复用状态必须由真机验证。
- 内存日志不持久化，复位后不能假设仍可读取。可用调试器、AP UART 或同次引导的 [Linux 接收路径](linux-log.md)读取；Linux 接收已在真机验证。
- 最小 DTB 仅承载探针交接；后续须从完整 Coachz DTS 和实际原厂交接数据生成 XNU ADT。

## 验证

主机检查覆盖：交叉编译、无未解析外部符号、Image 头和大小、FIT 中实际内嵌字节与哈希、FDT 截断及非法边界。主机检查不能证明 ERET、UART、原厂装载或真机运行。

2026-10-27 已通过 Linux 接收路径取回 entry EL2、current EL1、stage=3、handoff EL2 的硬件日志，首阶段探针验收通过。下一阶段据此研究显示恢复和 XNU 内存布局；完整 XNU／GIC／SMP 契约仍未验证。

## 无串口时的定时复位检查点

采用两个独立 FIT：`reset-el2` 留在原厂 EL2，诊断成功后等 3 秒；`reset-el1` 执行既有 EL2→EL1 路径，诊断成功后等 10 秒。两个版本都在 FDT 检查、目标 EL 检查与 PSCI 版本检查通过后，使用物理计时器等待，再调用 `PSCI_SYSTEM_RESET`。不配置显示、EC、存储或看门狗；失败或异常时保留内存日志并停止。

该方法只提供粗粒度的执行观察。分别测试两个镜像，观察从屏幕关闭到实际重新开机的时间；两次延时应明显不同。黑屏、固件拒绝后返回菜单、手动复位或非预期时间的重启都不算通过。定时复位也不能展示寄存器值，不能替代后续详细日志或显示驱动。

原厂分支同时把 EC PWM 设为零，因此首个无串口测试不尝试仅打开 GPIO / DSI 来恢复屏幕。图像打包工具只创建普通 GPT 文件，不打开磁盘设备，不自动写入任何硬件。

## 早期指令集约束

原厂交接时 MMU 已关闭；探针不依赖 FP/SIMD 状态。构建必须在后端 CPU 特性中显式关闭 `fp_armv8` 与 `neon`、开启 `strict_align`，不能只依赖 C 前端的 `-mgeneral-regs-only`。最终 ELF 依据 AArch64 `$x` / `$d` 映射符号区分代码和内嵌数据，再拒绝 FP/SIMD 计算、向量访存与 SVE 指令主类。该检查是早期探针的约束检查，不是完整指令集验证器。

## 匹配对照

`memory` 对照不能区分 PSCI_VERSION、等待和最终复位调用。后续使用 [仅抑制最终复位的匹配对照](control.md)：从已校验的 reset-el1 机器码只替换最终 SMC 为等长 NOP，其余 Image 字节与 FIT 配置保持相同，以减少编译布局干扰。该产物不重新定义原版的成功条件，也不作为启动修复。

## 可搬移 C 数据与系统级回归

后续定位到 mode7 起的包装器 ADT 检查使用了字符串指针聚合：Image 链接到零，ELF 链接器已把指针写为低地址，装载时却没有运行时重定位；最终 ELF 无重定位记录不能证明这些值可搬移。诊断标签也有相同缺陷。改为内联字符数组，并在两条构建路径以相同 CPU／生成码选项和宏定义编译实际 C 对象，拒绝已分配节中的 ABS64／ABS32／ABS16 及绝对 MOVW 符号重定位。固定数字形式的 XNU KVA 不属于包装器符号指针；2 MiB 对齐保留 PC 相对寻址关系。

新增 TCG 系统回归实际执行包装器入口、装载器、源码 XNU、MMU 指令和同步异常至 EL2 的返回，独立核对内嵌负载字节及严格读取结果。板级准入、日志导出和 Linux 入口由桩代替；模型中的缓存指令与计数不能证明 SC7180 物理缓存行为。它填补本机 PIC 动态库自动重定位及原先仅到 BRK 的指令重放缺口，真机验收边界继续独立保留。
