# SC7180 温度采集适配

2026-11-01：新增待接入的 SoC TSENS 只读驱动，尚未编译进 XNU 或实机验收。源码入口：[pending/thermal](../../platform/coachz-prelink/pending/thermal/README.md)，[固定源码与批注](../../platform/coachz-prelink/pending/thermal/SOURCES.md)。

## 本轮选择

已有电池、背光、键盘等路径正在推进，下一项选择依赖较少的芯片温度读取。相比直接实现动态调频或 EC 传感器系统集成，TSENS 只需核对两组 MMIO 布局和有效位，且可复用公开 UniXNU 的采样思路；其输出也能成为后续温控的输入。

先保留固件状态做只读采样，而非同时初始化控制器与调整频率。若固件没启用传感器，本阶段会明确报告不可用，下一轮依据真实寄存器状态决定初始化方案。

## 已编写

- 两组 bank、共 25 路，原始寄存器与逐通道状态，有效温度换算为 m°C。
- 版本、控制器、reset、sensor enable、TRDY、VALID 的检查，有限重读，每轮清除旧结果。
- 有效通道峰值和约 10 秒周期日志；初始报告保留各路值与失败状态。
- 独立候选补丁和 ADT 生成函数；未改活动 `series`、装载器或构建配置。

移植中发现固定版本 NativeQcomTsens 的 ready 检查使用 bit 3，Linux 的 SC7180 对应 TSENS v2 定义为 bit 0。新代码按后者实现，并有专门模型检查。这里只确认源码差异，真实寄存器仍待上机读取。

## 已做的主机验证

四项检查通过：独立 C 模型（六组关键行为）、实际装载器 Node 的 ADT 序列化、候选补丁在隔离夹具中应用并与源码一致、活动构建未启用。另在当前组装后 XNU 上下文文件的临时副本应用补丁成功。未编译任何 XNU 对象、未打包／写盘、未操作设备、未提交／推送。

## 下一次实机验收

由接手者接入并构建后，先取得两个 bank 的版本、控制／ready 和有效通道掩码；如未启用或未就绪，记录该结果，不算温度驱动验收通过。有效时再比较连续采样和 Debian 同通道读数，确认变化、单位、bank／sensor 对应，并单独记录实机证据。

尚未实现 TSENS 初始化／校准、阈值中断、DVFS、温控策略、PMIC NTC、iPadOS thermal 服务或休眠恢复。当前日志中的 bank peak 不直接代表完整 CPU 温度。后续先确定有效通道和读取失败策略，再选择限频阈值与迟滞。
