# XNU SoC 属性诊断检查点

version=8 是完整平台返回连续黑屏后的故障二分，不是新的完整平台启动里程碑。沿相同源码和 ADT，在 pe_arm_get_soc_base_phys 完成 device_type 与 ranges 读取、缓存写入后，第一条恢复栈帧指令前单条 HVC；不继续机器识别中的 CPU／时钟遍历、型号或调试配置。

比较继续重复完整平台、加入异常／panic 重定向和提前到 SoC 属性完成处返回。选择最后一种：减少未确认的原生执行范围，复用已验证的四层活动帧和受控 Linux 返回；避免一次改变异常体系与原始平台执行路径。若通过，后续故障范围可收窄到 SoC 属性完成之后；若不通过，仍不能仅凭黑屏确定具体指令或校验门。

## 输入和验收契约

保持固定完整源码、正常零 CPU 初值、原始非零 SoC ranges 和现有严格 ADT／命令行契约。独立 Python 解析给出 ranges 值偏移；C 装载器重新扫描真实节点并核对该偏移、24 字节大小和 DRAM 修补字段分离，全部检查先于 arena 写入。version=8 单独记录补丁边界，旧七模式保持独立。

返回时验证完整 SoC 缓存对象（指针、32 字节字符串区、真实父地址）、原有 PE／DT／CPU 数据和四层活动帧。SoC 帧的两个属性输出指针、最终属性大小、节点和所有保存字必须与独立树解析一致；x0 是 SoC 基址，x19 是缓存字符串，x20 是已审计 ADRP 页，LR 是最后属性调用返回位置。完整表池、硬件 AT、cache／FP 状态和 4 KiB 栈区底部的 64 字节 guard 保留。

此时型号、完整时钟块和调试配置尚未执行，相应全局必须保持原始值，不能沿用 mode7 的最终值。日志只要求既有平台 19 字段及 SoC 属性字段，共 20 字段；不得产生 clock info／PE return 成功字段。保留严格捕获与页表门限后的失败数据诊断返回，失败记录不算验收通过。

## 验证计划

覆盖单字补丁与源码审计、ranges 元数据／越界／错误属性／DRAM 修补重叠的写入前拒绝、全部新现场字段与活动帧／缓存对象破坏拒绝、未执行全局零值、严格 20 字段及失败标记、旧七模式兼容和实际包装器交叉编译。使用实际指令的主机对照补充核对返回现场；它不代替真机证据。签名普通镜像经独立审查、目标端校验与外置介质全量回读后，另行手动启动。

106 项完整主机回归通过；独立审查发现的测试字段偏移已修正，7 项新回归重跑通过。四种既有探针构建通过。实际源码指令从 CPU 初始化前重放到 SoC 函数 +0xb8，四项 C 数据验证器均通过，SoC／信息块／配置／PE／DT／游标与全部活动帧逐字节匹配。该对照不模拟真实 MMU／缓存维护，不能作为硬件验收。

生成包装器 6611 条指令、13 段通过标量约束；version=8、精确补丁 PC、源码／全部产物哈希、实际主备 GPT CRC／分区属性与内嵌容器核对通过。保留原有 Linux、47 份 DTB、initrd 和命令行。使用 `read_probe.py --xnu-soc` 验收；黑屏或恢复 Debian 本身均不算成功。
