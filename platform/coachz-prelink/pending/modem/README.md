# Coachz LTE modem: IPA configuration, ipa_setup, the QMI handshake and the data path

Compiled in place by drivers/RamBlock/coachz_modem.c, which includes coachz_ipa_cmd.c and coachz_ipa_rx.c (and now coachz_ipa_modem.c) in one translation unit (do not build them separately); on hardware it runs through the QMI handshake (see the result below). Chinese hand-off: [docs/plans/modem.md](../../../../docs/plans/modem.md).

MPSS already runs (coachz-prelink-wifi.patch: MBA/PIL, SMEM, SMP2P 435/428, GLINK, QRTR, rmtfs, the IPA clock vote and the SMP2P `ipa` clock query answered). Cellular data in mainline goes through the IPA: `drivers/net/ipa` with `qcom,gsi-loader = "modem"` on the LTE SKU (`sc7180-trogdor-lte-sku.dtsi`), then `rmnet` over the `rmnet_ipa0` netdev; network control (UIM, DMS, NAS, WDS, WDA) is userspace in Linux (libqmi/ModemManager). Mainline order:

1. **probe: IPA config (this directory)** (register setup, `ipa_mem_config` reads `mem_offset`, endpoint config, tables), SMP2P (`ipa-clock-query`, `ipa-setup-ready`).
2. the modem loads GSI firmware and raises `ipa-setup-ready` (SMP2P inbound bit 1) → `ipa_setup`: **GSI setup, endpoints, AP_COMMAND_TX, `ipa_mem_setup`, `ipa_table_setup`, AP_LAN_RX (this directory)** and default route, then `ipa_qmi_setup`.
3. **the QMI handshake (this directory)**: serve 0x31 instance 1, look up the modem's 0x31 instance 2, INIT_DRIVER with the v4.2 layout, answer DRIVER_INIT_COMPLETE and INDICATION_REGISTER, send INIT_COMPLETE.
4. `ipa_modem_start`: modem endpoints, the `rmnet_ipa0` netdev (QMAP), then rmnet on top.
5. QMI control: card status, operating mode online, registration, WDS start network, IP settings; data format through WDA.

## Integration (the integrating session)

Config: with the Wi-Fi patch's `wifi_ipa_power()` done, call `coachz_ipa_config(&ipa, zero_virt, zero_phys, wifi_qmp_send)` (`zero_virt`/`zero_phys`: 8 KiB of DMA-visible memory; the apps SMMU is in bypass). Linux runs it at probe, before the modem boots; the modem only raises `ipa-setup-ready` afterwards. Call `coachz_ipa_modem_starting()` where the MBA/PIL start begins (and clear our SMP2P `ipa` entry there, as `ipa_smp2p_notify_reset` does), and `coachz_ipa_interrupt()` from GIC SPI 311 or a poll. The Wi-Fi patch's `ipa: setup ready` log decodes SHARED_MEM_SIZE with the halves swapped: mainline reads MEM_SIZE from bits 15:0 and MEM_BADDR from bits 31:16 (`mem_offset` = 8 × bits 31:16).

GSI: at config time also call `coachz_gsi_init(&gsi, ipa.gsi, ring_virt, ring_phys, bytes)` with a zeroed, 64 KiB-aligned, write-combined or uncached block of at least 40 KiB (Linux allocates the rings at probe too); when `ipa-setup-ready` arrives, `coachz_gsi_setup()` is the first step of `ipa_setup`. Then `coachz_ipa_cmd_init(&cmd, &ipa, &gsi, virt, phys, bytes)` with at least 8448 zeroed, 128-byte-aligned DMA bytes (the 64 KiB ring block has room from offset 0xc000) and `coachz_ipa_setup_commands(&cmd)`: endpoint programming, command channel start, `ipa_mem_setup`, `ipa_table_setup`. Then `coachz_ipa_rx_init(&lan, &ipa, &gsi, CIPA_EP_AP_LAN_RX, virt, phys, bytes)` with a 128-byte-aligned write-combined or uncached block (2 MiB holds all 251 buffers, as Linux queues; a smaller block queues fewer) and `coachz_ipa_setup_lan_rx(&lan)`, which ends `ipa_setup`. Call `coachz_ipa_rx_poll(&lan)` when `coachz_gsi_interrupt()` sets the LAN RX event ring in `ieob_pending`, or periodically. `ipa_qmi_setup` (the handshake) follows; then `ipa_modem_start` and the `rmnet_ipa0` data path (not yet written).

Handshake: on the existing QRTR, add a server for service 0x31 instance word 0x101 (`CI_QRTR_INSTANCE(1)`), and on a NEW_SERVER with `ci_is_modem_service()` send `ci_init_driver_req()` to that node/port with the real `mem_offset` (step 1) and `uc_loaded`; on a success response call `ci_on_init_driver_success()`. Answer requests 0x20 and 0x35 arriving at the server with `ci_success_rsp()` and the matching `ci_on_*_answered()`. After each event run `ci_ready_step()`: send `ci_init_complete_ind()` when asked (then `ci_indication_sent()` and step again), call the modem start when asked. Steps 2 and 4 are the mainline IPA driver itself and come next; this layer only becomes meaningful after `ipa-setup-ready` and `ipa_setup`.

## Hardware facts so far

Under XNU (before any of this code was wired): the modem raises `ipa-setup-ready` (SMP2P `ipa` entry 0x2) although the AP had configured nothing, SHARED_MEM_SIZE is 0x415 (`mem_offset` 0; the reported 8360 bytes exceed ipa-shared, so `mem_size` stays 0x2000, as mainline does), and QRTR announces service 0x31 version 1 instance word 0x201. On Debian (mainline driver, setup completed, `rmnet_ipa0` present) the IPA and GSI registers were read through /dev/mem with the device held active: FLAVOR_0 0x08090811, HW_PARAM_2 0xe4046b59 (11 channels and event rings), the resource limits, COUNTER_CFG, IDLE_INDICATION every GSI channel and event ring context, the ten endpoint registers of all four AP endpoints, LOCAL_PKT_PROC_CNTXT (0x5f0, mem_offset 0 there too), ROUTE (0x01100050) and IRQ_SUSPEND_EN (0x100, LAN RX only while `rmnet_ipa0` is down) match what this code writes. CLKON_CFG (0), QSB_MAX_WRITES (0x78), QSB_MAX_READS (0x7800000c) and TX_CFG's PA_MASK_EN differ from what mainline writes at probe; the device had been runtime-suspended, mainline does not rewrite them on resume, so these are read as post-suspend values, and the code keeps mainline's probe values.

## Result on hardware (XNU, one boot, log ring)

Wired by drivers/RamBlock/coachz_modem.c in the order above, polled from the Wi-Fi thread's 1 ms loop (no SPI 311/432). All expected lines matched: SHARED_MEM_SIZE 0x415 (mem_offset 0, mem_size 0x2000), FLAVOR_0 0x8090811, HW_PARAM_2 0xe4046b59, all four AP channels and event rings allocated and modem channels 0xf, the two command transactions completed (LOCAL_PKT_PROC_CNTXT 0x5f0, ENDP_INIT_MODE[6] 0x83), LAN RX with 251 buffers, ROUTE 0x1100050, IRQ_SUSPEND_EN 0x100; CLKON reads 0x30000000 and QSB 0x8/0xc after configuration, as mainline writes them. No timeout, bad state, generic result or global error. The handshake reached INIT_COMPLETE: INIT_DRIVER (mem_offset 0, uc_loaded 0) was answered with success, the uC reported INIT_COMPLETED and the retention request was sent, then INDICATION_REGISTER and DRIVER_INIT_COMPLETE were answered. The state held for the 240 s logged, with the modem running and Wi-Fi unaffected; LAN RX received nothing.

Checked against mainline: requests 0x23 and 0x27 that the modem sends after INIT_COMPLETE have no handler in `ipa_server_msg_handlers` (only 0x20 and 0x35), and `qmi_invoke_handler` (drivers/soc/qcom/qmi_interface.c) returns without a response for an unhandled message, so logging them and not answering is mainline behaviour. `uc_loaded` 0 in the first INIT_DRIVER is expected: the modem loads the uC on its first boot, and `skip_uc_load` becomes 1 only for later modem boots. The response's `modem_driver_init_pending` 1 announces the second handshake (DRIVER_INIT_COMPLETE), which arrived; mainline decodes the response but uses only its result.

## Data path integration

After the handshake (`ci_ready_step` asks for the modem start): `coachz_ipa_rx_init(&modem_rx, &ipa, &gsi, CIPA_EP_AP_MODEM_RX, virt, phys, 2 MiB)`, `coachz_ipa_modem_init(&m, &ipa, &gsi, &modem_rx, tx_virt, tx_phys, bytes)` (2 KiB per TX slot; 1 MiB gives 505, the channel's limit), then `coachz_ipa_modem_start(&m)` and `coachz_ipa_modem_open(&m)`. Poll `coachz_ipa_rx_poll(&modem_rx)` for event ring 3 and `coachz_ipa_modem_tx_poll(&m)` for ring 2. Opening without a data call is what Linux does when rmnet_ipa0 comes up; nothing flows until QMI control (WDA data format, WDS bind to a mux id, start network) sets up a call, which is not written. Expected: "rmnet_ipa0 up: TX channel 0 (505 slots), RX endpoint 9 with 251 buffers, IRQ_SUSPEND_EN 0x300".

On hardware this passed: both rmnet_ipa0 lines matched, GSI channels 0 and 3 read state 2 (started) after open, and with no data call the modem RX counters stayed 0. No data has flowed yet.

## Next

The acceptance target is the iPadOS cellular UI (status bar, Settings > Cellular, APN, SIM and eSIM), not a kernel-dialled bare interface. The route is a bridge that presents Apple's baseband interfaces (AppleBaseband and AppleBasebandPCIControl user clients) to AppleBasebandManager and CommCenter, carries their QMUX traffic to QMI over QRTR, answers Apple-private services, implements VINYL (eSIM) with UIM APDUs and turns rmnet into pdp_ip. Research notes and open questions: docs/plans/modem.md, section "iPadOS 蜂窝界面和 eSIM".
