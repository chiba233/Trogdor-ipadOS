# Coachz usb_1 SoC bring-up (DWC3, QUSB2, QMP): stage 1

Not consumed by the kernel build; no kernel object was built and there is no hardware result. Chinese hand-off: [docs/plans/usb-c.md](../../../../docs/plans/usb-c.md). Pinned sources: [SOURCES.md](SOURCES.md).

Both USB-C ports of Coachz sit behind the onboard Realtek RTS5411 hub (2.x half on root port 1, 3.x half on root port 2) on the single DWC3 controller usb_1; the EC owns the Type-C ports (`cros-ec-typec`, both `data-role = "host"`), and the QMP combo PHY's DP side is not wired. Stage 1 ports the mainline sequence that brings that controller up in host mode, so the xHCI driver starts from a controller this kernel initialised rather than from firmware's state. Since the root disk moved to eMMC, re-initialising usb_1 no longer takes the root away.

## Files

| File | Purpose |
|---|---|
| `coachz_usb_proto.h` | Portable: board addresses, GCC offsets and RCG/GDSC values, the DWC3 register values the mainline core computes from the controller version, hwparams and trogdor's quirks, the xHCI protocol-capability port count, the QUSB2 v2 table and trogdor tuning, the HSTX trim decode, QMP block offsets and bits, the PHY supplies. |
| `coachz_qmp_tables.h` | Generated by `gen_qmp_tables.py` from the pinned `phy-qcom-qmp-combo.c` and its v3 headers (89 entries: serdes, tx, rx, pcs). Regenerate, do not edit. |
| `coachz_usb_soc.c` | Kernel side: `coachz_usb_soc_init()` (boot argument `coachz-usb-soc=1`), the whole sequence below. |
| `coachz_usb_rpmh.h` | Two additions this code needs from the shared RPMh client: CX consumer `COACHZ_CX_USB = 4`, and `coachz_rpmh_vreg_request` (per-consumer, aggregated LDO votes). **Not implemented here.** |

Host checks: `python3 -B -m unittest discover -s tests -p test_usb_soc.py -v` — the portable model (7 groups, ASan/UBSan), a type check of `coachz_usb_soc.c` against stub kernel headers (`-Wall -Wextra -Werror`), the generated tables' provenance and shape, and that the active build does not reference it.

## Sequence (mainline order)

1. `pp3300_hub`: gpio84 output high (boot-on fixed regulator; `onboard_usb_dev` enables `vdd`, `reset_us` 0, for both RTS5411 halves).
2. `USB30_PRIM_GDSC`: `gdsc_init` wait values, SW_COLLAPSE cleared, PWR_ON within 2 ms. CX at nom (`required-opps`).
3. Assigned rates: mock_utmi 19.2 MHz (XO), master 150 MHz requested → 200 MHz (GPLL0 main / 3; `clk_rcg2_ops` rounds up).
4. `dwc3-qcom-legacy` probe: `GCC_USB30_PRIM_BCR` assert, 10 µs, deassert; cfg_noc, core, iface, sleep, mock_utmi branches.
5. `dwc3_core_probe`: GSNPSID/VER_NUMBER, hwparams, xHCI port count.
6. `dwc3_core_init`: GUSB3PIPECTL (UX_EXIT_PX and SUSPHY off), GUSB2PHYCFG (SUSPHY off, ENBLSLPM off for `dis_enblslpm`); QUSB2 init (supplies ldoa4/ldoa11/ldoa17, cfg_ahb, BCR, POWERDOWN, v2 table, imp-res 8 / bias 0x22 / charge 3 / preemphasis 15 % half-bit / hsdisc 0, efuse HSTX trim, power up, single-ended clock, CORE_READY); QMP USB init (supplies ldoa4/ldoc3, phy BCR, aux/cfg_ahb/ref/com_aux/pipe clocks, DP_COM in USB3+DP mode with no orientation, serdes/tx/rx/pcs tables, START, PHYSTATUS clear within 10 ms); SUSPHY on (USB3 only: `dis_u2_susphy`); device-side soft reset; GUID; GCTL; event buffer; GUCTL2; GUCTL1 (L1 exit by HW, decoupled L1/L2 events, park mode off for SS, no forced 2.0 clock at super-speed).
7. `dwc3_core_init_mode`: PRTCAPDIR host (SUSPHY off first on DRD cores).

The xHCI (0x0a600000, SPI 133) is then ready for its driver's HCRST.

Not in stage 1: the glue's wake interrupts and suspend/resume, interconnect bandwidth votes, Type-C status from the EC, DisplayPort.

## Integration (the integrating session)

1. Add `COACHZ_CX_USB` (and `COACHZ_CX_CONSUMERS = 5`) and implement `coachz_rpmh_vreg_request` in the shared RPMh client with regulator-core aggregation: ldoa4 also feeds the DSI PLL, CSI, UFS and refgen. The SDHCI driver's direct VRM writes should move to the same call.
2. Compile `coachz_usb_soc.c` with its headers into `libCoachzUsb.a` (`build-usb-stack.py`) and call `coachz_usb_soc_init()` at the top of `coachz_usb_open()`, before `xhci_init()`; a return of 0 means the bring-up failed and must not fall through to `xhci_init()`.
3. Check the event buffer page `0x81130000` against the memory layout (after the SDHCI pool, below the speaker ring) and the io_submap budget (7 GCC pages, 56 KiB DWC3, 3 × 4 KiB + 12 KiB PHY/glue/fuse/GPIO, 4 KiB buffer).
4. Add `coachz-usb-soc=1` to a candidate image.

Expected log: `COACHZ usb: dwc3 ip 0x5533 revision … , 1 usb2 / 1 usb3 ports`, `qusb2 hstx trim N, pll status 0x…1`, `soc ready after … ms`, then the existing `COACHZ USB:` lines of `coachz_usb.c`. Acceptance on hardware: the keyboard and a USB drive on either USB-C port enumerate as before — the drive at SuperSpeed through the RTS5411 3.x half — with this bring-up in front of `xhci_init()`.

## Next stage

The host stack above the controller (Apple's `AppleUSBXHCI`/IOUSBHostFamily from the kernelcache on this DWC3, or another xHCI driver), hot-plug on both ports, Type-C status and power-delivery from the EC (`cros_ec_typec`), the glue's wake interrupts, bandwidth votes, then DisplayPort if the board routes it. Which host stack to use depends on the integrating session's evaluation and a hardware result, so it is not written here.
